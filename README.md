# Завод TMK — Android-приложение

Готовый проект Android Studio: WebView-обёртка вокруг того же контента,
что и веб-приложение (PWA) — 3D-модель завода, схема технологических
потоков, галереи чертежей оборудования и исходные PDF по проекту.
Все страницы и картинки лежат внутри APK, в `app/src/main/assets/www/`,
и открываются полностью офлайн (кроме вкладки «3D-модель» — она грузит
библиотеку three.js с CDN при первом запуске, см. ниже).

## Почему нет .apk в архиве

В среде, где собирался этот проект, нет Android SDK и нет доступа к
серверам Google/Maven, откуда качаются компоненты для сборки — поэтому
собрать .apk «на месте» невозможно технически. Сам код и все ресурсы
полностью готовы; собрать из них .apk может Android Studio на обычном
компьютере за несколько минут.

## Как собрать .apk

1. Установите **Android Studio** (последняя стабильная версия,
   https://developer.android.com/studio).
2. `File → Open…` → выберите папку `android-project` (эту, где лежит
   файл `settings.gradle`).
3. Android Studio сам предложит скачать нужную версию Gradle и Android
   SDK (потребуется интернет один раз, при первом открытии проекта) —
   согласитесь на всё автоматически предлагаемое («Sync Now» / «Install
   missing SDK component(s)»).
4. После синхронизации: `Build → Build Bundle(s) / APK(s) → Build APK(s)`.
   Готовый файл появится в
   `app/build/outputs/apk/debug/app-debug.apk`.
5. Чтобы установить на телефон: скопируйте `app-debug.apk` на устройство
   и откройте (разрешите установку из неизвестных источников), либо
   подключите телефон по USB и нажмите ▶ Run в Android Studio.

Версия плагина Android (`com.android.application`) в `build.gradle` сейчас
стоит `9.0.1` — подходит для Gradle 9.1.0 и новее (что покрывает свежие
версии Gradle, включая 9.3.x). Если у вас установлена более старая версия
Gradle, Android Studio сама предложит либо обновить Gradle, либо поднять
версию плагина ещё дальше («Upgrade Assistant»).

Если при открытии проекта появляется ошибка вида «Cannot mutate the
dependencies of configuration ... after the configuration was resolved» —
это несовместимость версий Gradle и плагина Android (AGP), а не проблема с
самим кодом. Чаще всего лечится через `File → Sync Project with Gradle
Files` после обновления версии плагина в `build.gradle`, либо
`File → Invalidate Caches / Restart…`, если после правки версии ошибка не
пропала.

## Структура проекта

```
android-project/
├── settings.gradle, build.gradle, gradle.properties   — конфигурация Gradle
├── app/
│   ├── build.gradle                — модуль приложения (applicationId, SDK версии)
│   ├── src/main/
│   │   ├── AndroidManifest.xml     — разрешения (INTERNET), единственная Activity
│   │   ├── java/.../MainActivity.java — полноэкранный WebView, грузит assets/www/index.html
│   │   ├── res/                    — иконка приложения, тема, название
│   │   └── assets/www/             — сам сайт (index.html + 3 вкладки + все чертежи/PDF)
```

## Что внутри `assets/www/`

- `index.html` — оболочка с нижней панелью вкладок (3D-модель / Схема потоков / Документы)
- `model.html` — 3D-модель завода (Three.js)
- `flow.html` — интерактивная схема технологических потоков + таблица оборудования +
  нормы режима + галереи чертежей на каждый аппарат (123 файла, все офлайн)
- `docs.html` — перечень отделений завода и 13 исходных PDF-чертежей (планы
  размещения оборудования и P&ID), из которых сделаны галереи
- `vendor/` — three.min.js и OrbitControls.js (для вкладки «3D-модель»,
  полностью офлайн, без CDN)
- `sec_img/` — все растровые чертежи (JPEG)
- `docs_pdf/` — все 13 исходных PDF-листов проекта (23 МБ), полностью офлайн;
  ссылки на них — во вкладке «Документы»
- `manifest.json`, `service-worker.js` — для параллельной публикации как
  устанавливаемого веб-приложения (PWA); внутри Android-приложения не обязательны,
  но не мешают

## Просмотр PDF-чертежей

WebView (компонент, которым открывается сайт внутри приложения) сам PDF не
отображает. Поэтому `MainActivity.java` перехватывает клики по ссылкам на
`.pdf` во вкладке «Документы», копирует нужный файл из `assets/` во
внутренний кэш приложения и открывает его системным просмотрщиком PDF через
`Intent.ACTION_VIEW` (стандартный, безопасный способ — через `FileProvider`,
без прямого доступа сторонних приложений к файлам внутри APK). Если на
телефоне не установлено ни одного приложения для чтения PDF, появится
короткое сообщение об этом — тогда нужно поставить любую PDF-читалку
(например, Google PDF Viewer или Adobe Acrobat) из Play Store.

## Иконка приложения

Иконка — эмблема TMK Chemicals (кружок-шестерёнка с волной в центре),
перерисованная по вашему логотипу в векторном виде синим фирменным
цветом на белом фоне (сам присланный файл — маленький скриншот, размытый
при увеличении, поэтому эмблему перерисовал заново, чтобы она была чёткой
на любом размере экрана).

Есть полный набор: обычные иконки для старых Android (mdpi…xxxhdpi,
квадрат/круг) и адаптивная иконка для Android 8.0+ (`mipmap-anydpi-v26`) —
на разных лаунчерах она сама примет нужную форму (круг, квадрат со
скруглением, капля и т.д.). Ничего дополнительно настраивать не нужно, она
уже подключена в `AndroidManifest.xml` (`android:icon="@mipmap/ic_launcher"`).

## Офлайн-работа вкладки «3D-модель»

Библиотека three.js (r128) и OrbitControls.js встроены в приложение
локально — `app/src/main/assets/www/vendor/three.min.js` и
`vendor/OrbitControls.js`, `model.html` подключает их относительным путём
(`<script src="vendor/three.min.js">`). Раньше они грузились с CDN
(`cdnjs.cloudflare.com`, `cdn.jsdelivr.net`), из-за чего вкладка не
работала без интернета при первом запуске — теперь вся 3D-модель полностью
офлайн, как и остальные вкладки, сразу после установки APK.

## Обновление данных из Google Диска (без пересборки APK)

Приложение больше не читает контент напрямую из APK: при первом запуске
оно копирует всё из `assets/www/` во внутреннюю память приложения
(`getFilesDir()/www/`), а дальше при каждом запуске (и по кнопке «⟳» в
шапке) тихо проверяет ОДНУ папку на Google Диске — без всплывающих окон,
если ничего не поменялось. Никакого файла-описи вести не нужно: что лежит
в этой папке на Диске (включая вложенные подпапки), то и скачивается в
приложение, с той же структурой. Нужно обновить чертёж — просто замените
файл в папке на Диске, и при следующем запуске приложение подтянет
изменения само.

Если найдена новая версия — приложение НЕ скачивает её молча: сначала
показывает диалог «Доступно обновление данных» с числом файлов и размером
в МБ, и только по нажатию «Скачать» начинает загрузку. Пока файлы
качаются — на экране полоса прогресса («Файл N из M») с кнопкой «Отмена»:
если нажать её в любой момент, докачка остановится, уже скачанные файлы
останутся, а недокачанные попробуются заново при следующей проверке (это
не портит уже работающее приложение — обновляются файлы по одному, а не
всё сразу).

### Как настроить

Нужны две вещи: ID папки на Google Диске и API-ключ (без ключа Google не
даёт даже посмотреть список файлов в папке — это его требование, не моё).

**1. Папка на Google Диске**
- Создайте папку на Google Диске, положите туда файлы, которые хотите
  обновлять (например, исправленный PDF-чертёж) — можно с подпапками,
  структура повторится и в приложении (файл в подпапке `docs_pdf/` на
  Диске попадёт в `docs_pdf/` внутри приложения).
- Правой кнопкой по папке → «Открыть доступ» / «Share» → поменять на «Все,
  у кого есть ссылка» (это обязательно, без этого приложение ничего не
  увидит) → «Копировать ссылку». Получится ссылка вида
  `https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrSt?usp=sharing` —
  нужна часть после `/folders/` и до `?` (в примере
  `1AbCdEfGhIjKlMnOpQrSt`).
- Пришлите мне эту ссылку (или просто идентификатор) — я вставлю её в
  `MainActivity.java` вместо `PUT_GOOGLE_DRIVE_FOLDER_ID_HERE`.

**2. API-ключ Google Drive API** (бесплатный, разовая настройка на 2 минуты)
1. Откройте https://console.cloud.google.com/ (нужен обычный Google-аккаунт).
2. Если проекта ещё нет — создайте новый (кнопка вверху "Select a project" →
   "New project", любое название).
3. В меню слева: "APIs & Services" → "Library" → найдите "Google Drive
   API" → "Enable".
4. "APIs & Services" → "Credentials" → "Create Credentials" → "API key".
   Появится ключ вида `AIzaSyD...` — скопируйте его.
5. (Не обязательно, но правильно) Нажмите на созданный ключ → в разделе
   "API restrictions" выберите "Restrict key" → отметьте только "Google
   Drive API" → Save. Так ключ будет работать только для чтения Диска и
   ни для чего больше, даже если куда-то утечёт.
6. Пришлите мне этот ключ вместе со ссылкой на папку — я вставлю его
   вместо `PUT_GOOGLE_DRIVE_API_KEY_HERE`.

После этого всё готово — ничего больше редактировать не нужно, обновления
управляются полностью через содержимое папки на Диске.

### Важно

- Обновляется абсолютно всё, что лежит в указанной папке на Диске (и в её
  подпапках) — если файл туда не положен, он останется таким, каким был
  собран в APK.
- Имена файлов и подпапок на Диске должны совпадать с именами внутри
  `assets/www/` (например, файл `G111-07-plan-000.pdf` нужно класть в
  подпапку `docs_pdf` на Диске, чтобы он лёг в `docs_pdf/` в приложении;
  файл прямо в корне папки на Диске обновит файл с тем же именем в корне
  сайта, например `index.html` или `model.html`).
- API-ключ виден внутри собранного APK (это обычное дело для такого рода
  ключей, не секрет уровня пароля) — с ограничением из шага 5 выше им
  можно только читать содержимое Google Drive, поэтому это не проблема
  безопасности.
- Для скачивания нужен интернет на телефоне; если его нет — приложение
  просто открывается с тем содержимым, что уже скачано/встроено, без
  ошибок и без блокировки интерфейса.
