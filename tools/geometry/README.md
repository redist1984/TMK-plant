# Проверки геометрии 3D-модели

Независимые проверки того, что модель сходится физически: трубы не проходят
сквозь аппараты, аппараты не висят в воздухе, ничего не протыкает стены и
крыши зданий, приборы КИП не влезают в чужое оборудование.

## Запуск

```powershell
npm install              # один раз: playwright-core
npm run geometry         # все проверки
npm run geometry -- --only pipe-pipe
npm run geometry:baseline   # перезаписать базовую линию
```

Браузер **не скачивается**: используется установленный Chrome
(`--browser msedge`, если Chrome нет). На Linux в CI — тоже системный Chrome.

Под капотом: `prepare.js` делает `model_test.html` (копия `model.html` плюс
одна строка, выставляющая `window.__T` с объектами сцены — в самом
`model.html` их наружу не отдают), поднимается локальный HTTP-сервер на
свободном порту, всё прогоняется в одном браузере.

## Как это читается

Каждая проверка печатает число находок и первые 12 строк. Опоры — не «ошибки
сборки», а список мест, где аппарат стоит без видимой опоры; их разбирают
глазами, поэтому в CI сравнивается только **количество**.

`tools/geometry/baseline.json` — зафиксированное текущее состояние. Проверка
падает, если находок стало **больше** базовой линии плюс допуск (то есть
модель ухудшилась). Улучшения базовую линию не ломают — её обновляют вручную
после разбора.

**Почему модель «прыгает» и что с этим сделано.** В `model.html` цикл
анимации непрерывно двигает мостовые краны: мост едет по рельсам, тележка по
пролёту, крюк ходит по высоте (`rope.scale.y`). У `LR-12101` крюк опускается на
2…7,5 м, поэтому габарит крана меняется на метры от кадра к кадру — и любая
проверка на `Box3` получала разные числа.

Раннер перед замерами **останавливает кадры** (`window.requestAnimationFrame`
заменяется на пустую функцию) и **ставит краны в фиксированное положение**:
мост и тележка в нуль, крюк поднят до `o.L[0]`. Сама модель при этом не
меняется — это только её состояние.

Результат: два прогона подряд дают побайтово одинаковые числа и габариты
(`LR-12101` → 9.35 м в обоих). В CI остаётся небольшой допуск
`TMK_GEO_TOLERANCE=2` — запас на разницу версий Chrome между машиной и раннером.

Актуальная базовая линия (в «спокойном» состоянии):

| Проверка | Находок | Время |
|---|---|---|
| `pipes-through-equipment` | 6 | ~4 мин |
| `pipe-pipe` | 40 | ~1 с |
| `supports-overlaps` | 352 | ~4 с |
| `walls-roofs` | 32 | ~0,2 с |
| `kip-overlaps` | 143 | ~1,5 мин |

Две проверки медленные: они перебирают точки трасс с шагом 0,25–0,4 м и
кастят лучи во все стороны. Для быстрой итерации: `--only pipe-pipe` и т. п.

## Ограничения

- В песочнице DSH браузер не запускается (`spawn EPERM` — playwright
  поднимает Chrome с управляющим pipe, а песочница это блокирует). Локально
  нужен запуск с расширенным доступом; в CI и в обычном терминале работает.
- Шейдерные ошибки swiftshader в headless игнорируются: геометрия к этому
  моменту построена, на результаты они не влияют. Настоящие ошибки JS
  по-прежнему считаются провалом.
- `tools/query-*.js` (bbox / region / flow) остались от старого окружения и
  пока не портированы.
